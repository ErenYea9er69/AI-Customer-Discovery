# GitHub

## Rules to follow

- [official] GitHub's Acceptable Use Policies ban spam, bulk automated activity that harms the platform, and deceptive behavior. Many repositories also set their own contributing guides.
- [practice] Maintainers dislike comments that only promote a product. A comment must help with the issue.

## When to comment

Comment when all of these hold:

1. The issue is open, not locked, and not a pull request.
2. The issue describes the same problem your product solves, in a way the maintainers have not solved.
3. The reply answers the question or gives a workaround that works without your product.
4. You state the affiliation in the first or second sentence.
5. You have not commented on other issues in the same repository in the last 7 days.

## What the app does

- The harvester searches open issues created in the last 365 days and drops pull requests, locked issues, closed issues, bot authors and issues opened by maintainers.
- The reply style is short and practical, under 120 words.
- Automatic posting is possible with a token the owner supplies in the environment. It stays behind every gate and posts a single comment. Manual posting remains the default.

## Style

- Name the issue's symptom in the first sentence.
- Give a workaround first, then the product as one option, with affiliation.
- No marketing language. No links unless the issue asks for one.
- Never comment on an issue older than a year unless it is still active.
